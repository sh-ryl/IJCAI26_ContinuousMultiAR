## 3. Model Training

To train a new RL policy, run:

```bash
python python_agent.py train multivar uvfa pref ability craft_loc
```

The preference weights for the RL policy are configured in `scenario.py` under `scenarios["train"]["attr_sets"]` (line 32). For example:

```python
scenarios["train"]["attr_sets"] = [
    {"axe": 1, "bridge": 1, "plank": 1}
]
```

**Training outputs** are saved automatically to `mod/ag/<exp_param_path>/<attr_config>/`:
- `model.chk` — saved model checkpoint (best evaluation score)
- `training_scores.csv` — frame number and average evaluation score, logged periodically during training

> **Note:** With `uvfa` enabled, the ability level is sampled uniformly from `[0, 1200]` at the start of each episode, so the policy learns to generalise across the full ability range.

## 4. Model Evaluation (Based on Experiments — Section 4)

**Steps:**

1. For each attribute, configure `scenario.py` as described in [4A](#4a-preferences) and [4B](#4b-ability-level) below.
2. Run the following command:

```bash
python python_agent.py eval multivar uvfa pref ability craft_loc AR modbi
```

3. When prompted:
   - **AR log label** — enter a label to identify this run's output (or press Enter to skip).
   - **Model selection** — the observer will list all compatible trained models it finds. Press Enter to include all, or follow the prompts to select or remove specific ones.

### 4A. Preferences

Set the observed agent's preference by editing `scenarios["eval"]["attr_sets"]` in `scenario.py`. The list should contain a single dictionary mapping craftable items to weights that sum to one:

```python
scenarios["eval"]["attr_sets"] = [
    {"cloth": 0.9, "stick": 0.1}
]
```

Use the following format for the four-item preference vector:

```python
{"cloth": A, "stick": B, "plank": C, "rope": D}
```

where `A`, `B`, `C`, `D` ∈ `[0, 1]` and `A + B + C + D = 1`. The preference configurations used in the paper are:

| Configuration | Values | Description |
|---|---|---|
| Strong cloth preference | `{"cloth": 0.7, "stick": 0.1, "plank": 0.1, "rope": 0.1}` | One dominant item |
| Strong rope preference | `{"cloth": 0.1, "stick": 0.1, "plank": 0.1, "rope": 0.7}` | One dominant item |
| Weak cloth preference | `{"cloth": 0.4, "stick": 0.2, "plank": 0.2, "rope": 0.2}` | Mildly dominant item |
| Weak rope preference | `{"cloth": 0.2, "stick": 0.2, "plank": 0.2, "rope": 0.4}` | Mildly dominant item |

### 4B. Ability Level

When the `ability` flag is active and `uvfa` is **not** used (i.e. testing a single fixed ability), you will be prompted to enter the ground-truth ability level at runtime:

```
Enter ability level for player (Ground Truth, values between 0-1200):
```

The ability levels used in the paper span `[0, 1200]`, with representative values of `100, 300, 500, 700, 900, 1100` (low to high competence).

When `uvfa` **is** active (as in the evaluation command above), the agent's ability is randomised per episode — the observer must infer it from behaviour alone.

Crafting difficulty is set by the `craft_loc` flag, which assigns difficulty by location:

| Crafting Station | Difficulty Threshold |
|---|---|
| Workbench | 100 |
| Factory | 100 |
| Toolshed | 500 |

| Path | Contents |
|---|---|

| `check_out/` | Console output logs (only when `co` flag is used) |

## 6. Flag Reference

All flags are passed as positional arguments after the mode (`train` or `eval`). Order does not matter except for the mode, which must come first.

```bash
python python_agent.py <mode> [flags...]
```

### Mode

| Flag | Description |
|---|---|
| `train` | Training mode. Trains a new RL policy from scratch. |
| `eval` | Evaluation / test mode. Loads a saved model and runs the AR observer. |

### Attribute Flags

| Flag | Description |
|---|---|
| `pref` | Enables the **preference** attribute. The policy/observer is conditioned on item preference weights. |
| `ability` | Enables the **ability level** attribute. Controls crafting success probability. In test mode without `uvfa`, prompts for a ground-truth ability value. |
| `belief` | Enables **hidden items** (belief attribute). Certain items are hidden from the agent's observation. |

### Policy Architecture Flags

| Flag | Description |
|---|---|
| `uvfa` | **Universal Value Function Approximation.** The Q-function is conditioned on the attribute configuration, allowing a single policy to generalise across the entire attribute space. In training, the ability level is randomised per episode. |
| `multivar` | **Multivariate mode.** Trains/evaluates a single Q-function jointly conditioned on *all* attributes (preference + ability). Required for the experiments in Section 4 of the paper. |

### Crafting Difficulty Flags

| Flag | Description |
|---|---|
| `craft_loc` | Assigns crafting difficulty by **location**: Workbench/Factory → 100, Toolshed → 500. Used in the paper's experiments. |
| `craft_item` | Assigns crafting difficulty by **item type**: Plank → 100, Bridge → 400, Axe → 700. Also extends max steps to 200. |

### AR Observer Flags

| Flag | Description |
|---|---|
| `AR` | Activates the **Attribute Recogniser** observer. Prompts for a log label, then loads trained models to perform online inference. |
| `modbi` | **Modified Bayesian Inference.** Enables the continuous inference pipeline from Section 3.2: fits a scaled joint pdf (truncated log-normal for ability, ALR-transformed Normal for preference) to the posterior density samples. Required for the continuous inference experiments (Section 4.2). |

### Miscellaneous Flags

| Flag | Description |
|---|---|
| `render` | Renders the CraftWorld environment visually and prints per-step action probabilities and inventory. |
| `limit` | Limits max inventory for collectible ingredients (grass, iron, wood) to 1. |
| `degrade` | Enables **tool degradation** — tools lose effectiveness over time. |
| `incentive` | Enables an additional **incentive reward** signal. |
| `co` | Redirects all console output to a timestamped file under `check_out/`. |
